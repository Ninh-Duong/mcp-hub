# PR Companion MCP contract

- Repository: sibling `../mcp-pr-companion` (Node 20.12+). Its own rules: `../mcp-pr-companion/AGENTS.md`.
- Hub discovers this supported sibling automatically from the relative path. No private Hub config is needed unless overriding or disabling it; `hub__status` reports detection and connection.
- Transport: local stdio process launched by the Hub as `node bin/cli.js server` in the child repo (`config/private/mcps/mcp-pr-companion.json`, template `config/mcps/mcp-pr-companion.example.json`). `bin/cli.js` runs `npm ci` / `npm run build` when needed; `prepare` does this explicitly. On Windows, `inheritEnv` includes `APPDATA`, `LOCALAPPDATA`, `PATHEXT`, and `COMSPEC` for npm.
- Configuration: follows [Configuration sources](../child-mcp-compatibility.md#configuration-sources). The private config's `env.CENTRAL_CONFIG_PATH` points the child to that same file (relative to the child repo root); the launcher `bin/cli.js` reads its `bitbucket` block: `email` → `BITBUCKET_EMAIL`, `api_token` → `BITBUCKET_API_TOKEN`, `workspace` → `BITBUCKET_WORKSPACE`, `repository` → `BITBUCKET_REPOSITORY`, `allowed_emails` → `ALLOWED_EMAILS` (string or list). Priority per value: `env` > the `bitbucket` block > the child's `.env` > default; empty values fall back to `.env`, and a missing or unreadable Hub file is logged as a warning (error code only) and `.env` is used. Other settings stay in the child's `.env` or the config's `env` (`TICKET_PREFIXES`, `AUTO_SYNC_ON_START`, `PRIVACY_*`, `AI_CONTEXT_*`, `DEBUG`). Agents must not read `.env`. `BITBUCKET_REPOSITORY` supplies defaults to `list_my_open_prs`, `list_synced_prs`, and `sync_my_open_prs`, and is used by `AUTO_SYNC_ON_START`, `node bin/cli.js check`, and `node bin/cli.js sync <mode>`. Optional non-secret overrides can go in the child config's `env`, e.g. `env.PRIVACY_FILE_PATH_MODE`; never set it to `full` under the Hub because that returns real paths.
- `timeoutSeconds` is 300 because the first sync of a large PR downloads a full diff and the sync tools can process many PRs.
- Data at rest: everything in the child's `ai-context/` is encrypted (AES-256-GCM, key derived from the repository UUID). Tools that read local data unlock the relevant repository with a Bitbucket access check; a successful unlock is cached for 60 seconds per repository. Details: `../mcp-pr-companion/docs/ENCRYPTION.md`.
- Canonical storage groups are `open`, `draft`, `merged`, and `declined`. The group reflects the last successful sync; draft PRs have Bitbucket state `OPEN` and the draft flag set. Readers also search legacy status-less paths. When status or draft state changes, a successful sync publishes and validates the encrypted revision before migrating retained revision directories from old paths. Cross-volume copies use `readSecure` / `writeSecure`, verify decrypted contents, and preserve revision directory times for retention sorting. A fresh validated revision replaces an old active revision with the same ID. Failed migration or a conflicting history destination leaves the source readable for a later retry; unresolved conflicts remain there until the destination is repaired.
- `AUTO_SYNC_ON_START=true` makes each server launch sync the configured account's open PRs in the background.
- Bitbucket requests are read-only `GET`s. `fetchWithRetry` retries 429 and 5xx responses twice; other responses are not retried. No tool writes to Bitbucket.

## Tools

All tools return MCP text content containing Markdown or JSON. Errors are marked `isError` and text begins `Error:`. The child sanitizes returned content and error text. The ten exposed aliases below match the names in `config/hub.example.json`.

| Hub tool | Inputs and defaults | Behavior, output, and side effects | MCP annotations |
|---|---|---|---|
| `pr__get_pr_context_pack` | Required `pr_url`; `refresh=false`; `include_file_table=false` | Checks access, then compares commits in `current.json` and state/draft flag in the active manifest. Syncs if missing, changed, or migration is pending, unless `refresh=true` forces sync. Returns Markdown with Read Strategy, overview, change summary, description, and commits; optional full file table. Appends live approvals, build results, and review threads. Build counts exclude statuses linked to an older source commit, which are labeled separately. Writes the encrypted local cache. If freshness cannot be checked after access succeeds, returns cached context prefixed with a `Note:`. | `readOnlyHint=false`, `openWorldHint=true` |
| `pr__search_pr_files` | Required `pr_url`; optional `path`, `language`, `status` (`added\|modified\|deleted\|renamed`), `change_kind`, `risk_tag`; `limit=50` (1–200) | Reads the synced local revision after access unlock. Returns JSON `{total, files}`; path substring matching is case-insensitive and uses sanitized paths. Does not fetch PR details. | `readOnlyHint=true`, `openWorldHint=true` |
| `pr__get_pr_file_context` | Required `pr_url`, `file_id` (string or nonnegative integer); `offset=0`; `max_chars=16000` (500–100000) | Reads a synced local revision after access unlock. Returns Markdown for one file and a sanitized diff page; if more remains, ends with `continue with offset N.` Does not fetch PR details. | `readOnlyHint=true`, `openWorldHint=true` |
| `pr__get_pr_file_changes` | Required `pr_url`, `file_id` (string or nonnegative integer); `include_patch=true`; `offset=0`; `max_chars=16000` (500–100000) | Reads a synced local revision after access unlock. Returns JSON `{change, patch?}` where `change` includes classification/evidence, risk level/tags/evidence and symbols; included `patch` is `{text,total_chars,next_offset}`. Does not fetch PR details. | `readOnlyHint=true`, `openWorldHint=true` |
| `pr__get_pr_comments` | Required `pr_url`; `include_resolved=true`; `offset=0`; `limit=50` (1–200) | Fetches comments live from Bitbucket and returns JSON `{total,complete,comments,next_offset}`. Comment text is sanitized; author is included only when `PRIVACY_REMOVE_AUTHOR=false`; synced inline comments can include `file_id`, sanitized `path`, and `line`. Read-only; no cache write. | `readOnlyHint=true`, `openWorldHint=true` |
| `pr__list_synced_prs` | Optional `repository` (`workspace/repo`; omitted uses every `BITBUCKET_REPOSITORY` entry); optional `status` (`open\|draft\|merged\|declined`); `offset=0`; `limit=50` (1–200) | Lists locally synced revisions after unlocking each repository. Returns JSON `{total, prs:[{pr_url,repository,id,title,pr_status,updated_at}], next_offset}`. It does not discover or refresh PRs from Bitbucket. | `readOnlyHint=true`, `openWorldHint=true` |
| `pr__list_my_open_prs` | Optional `repository` (`workspace/repo`; omitted uses every `BITBUCKET_REPOSITORY` entry) | Discovers open PRs authored by the configured account. Returns JSON `{total,prs:[{pr_url,repository,id,title,is_draft,source_branch,target_branch,updated_on,local}]}`; `local` is `missing`, `cached`, or `outdated`. Live Bitbucket reads; no cache write. | `readOnlyHint=true`, `openWorldHint=true` |
| `pr__sync_my_open_prs` | Optional `repository` (same default as above); `force=false` | Discovers and syncs the account's open PRs, three at a time. Without force, skips PRs whose commits, state, draft flag, and storage location match; unchanged PRs cost one metadata request. Returns JSON `{total,synced,unchanged,failed,prs:[{pr_url,id,title,status,ticket,overall_risk,files_changed,updated_on,error?}]}`. Writes only the encrypted local cache; one failed PR does not stop the batch. | `readOnlyHint=false`, `openWorldHint=true` |
| `pr__check_bitbucket_connection` | No inputs | Read-only health tool. Makes one Bitbucket request to verify credentials and `ALLOWED_EMAILS`; returns `{"connected":true,"config_source":{"credentials","workspace","repository","allowed_emails"}}` on success (each `env`, `hub`, `local` or `unset`; `credentials` is the token's source) and an error on failure. It does not check a particular repository's access, unlock the encrypted cache, or perform the broader local readiness checks of `node bin/cli.js check`. | `readOnlyHint=true`, `openWorldHint=true` |
| `pr__get_pr_sync_status` | Required `pr_url` | Reads cache after access unlock. Returns `{synced:false}` or JSON with `synced`, `revision`, `updated_at`, source/target commits, `ai_reading_mode`, `pr_status` and stats. It does not fetch PR metadata; access unlock itself may make one Bitbucket request. | `readOnlyHint=true`, `openWorldHint=true` |

All tools that touch local encrypted data (including list and file readers) require repository unlock. The successful access check is cached for 60 seconds per repository. `check_bitbucket_connection` is a general credential/allowlist check; it does not establish access to every repository. `list_my_open_prs` and `get_pr_comments` are live Bitbucket readers. `get_pr_context_pack` reads cache and checks freshness, syncing when needed. The file, status, and synced-list tools read local cache; only their repository unlock may contact Bitbucket. `sync_my_open_prs` and context-pack sync write local cache only.

## CLI sync and cache migration

To sync historical PR states, the user runs `node bin/cli.js sync <open|draft|merged|declined|all>` in the child repo. This command scans every page for the selected states and filters to PRs authored by the configured account across `BITBUCKET_REPOSITORY`; `open` excludes drafts and `all` combines the four groups. It writes the encrypted local cache. An interrupted pagination run is marked incomplete and exits with an error code; rerunning the command can complete it. The MCP `sync_my_open_prs` remains open-only.

After a pre-encryption file is detected, the reader treats that PR as unsynced. A later successful sync writes encrypted data and prunes old plaintext revisions. The user can instead run `node bin/cli.js purge-plaintext` to delete all non-encrypted files under `ai-context/` without network access, then sync again. For interrupted status-directory migration, the newly validated revision is retained and the old encrypted directory remains readable; a subsequent successful sync retries migration even when the PR is unchanged. A same-named historical revision is removed from the source only after its destination decrypts to the same content. Never inspect or copy `ai-context/` with file tools or scripts; use the MCP tools.

## Working guidance

- To sync open PRs, call `pr__sync_my_open_prs` with a repository when useful and show its `prs` as a table. Include failed rows and their `error`.
- Use `pr__list_synced_prs` to find already cached PRs and `pr__list_my_open_prs` to discover the account's current open PRs. Pass each `pr_url` to the context tool.
- The file tools require a prior sync and return `Error: PR is not synced yet…` otherwise. Start with the Read Strategy and open only `Read next` file ids, then `Optional` if needed. For re-review, open the ids listed in “Changed since last sync”.
- For review feedback, call `pr__get_pr_comments` with `include_resolved=false`, then open each synced inline comment's `file_id` where present.
- Keep paging with `next_offset` or `continue with offset N`; do not raise `max_chars` just to read a large PR at once.
- If the context pack begins `Note: could not check Bitbucket…`, the result is cached and may be stale. State that when using it.
- A `No access` error means the access check failed (credentials, `ALLOWED_EMAILS`, repository read access, or network). Tell the user; never work around it or read encrypted files directly.
- Sanitized paths and text are intentional; do not try to recover the original values.

## Hub integration and diagnostics

- The Hub smoke check uses `pr__check_bitbucket_connection` and expects `connected: true`. Child self-check `node bin/cli.js check` separately checks Node, dependencies, build, and required settings, including `BITBUCKET_REPOSITORY`, and prints their sources on its Config line; it is not an MCP tool.
- Child logs are in `../mcp-pr-companion/Logs/mcp-server.log` (launcher errors use `[LAUNCHER]`). Hub events are in `logs/mcp-hub.jsonl`.
- `Error: No access: Bitbucket rejected the credentials (HTTP 401)` indicates invalid credentials; fix them where `config_source.credentials` says (`hub`: the `bitbucket` block, `local`: the child's `.env`). `Failed to fetch PR metadata: HTTP 403` generally indicates a missing `read:pullrequest` or `read:repository` scope. `Error: No access: this account cannot read <ws>/<repo>` means the account lacks repository access. A network failure prevents unlocking the encrypted cache.
- An `Unencrypted ai-context file` error indicates pre-encryption data; run `purge-plaintext` or resync that PR.
